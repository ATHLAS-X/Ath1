System Overview
End-to-End Pathway Platform

How each role interacts with the system over time, across the whole product: Auth, onboarding, dashboards, and all nine association-pivot workflows. Use case and class diagrams have been removed from this set - they were not rendering reliably.

Sequence

Master / Whole-Site View

sequenceDiagram
    participant U as New User
    participant Auth as Auth and Router
    participant Onb as Onboarding (role-specific)
    participant Dash as Dashboard (role-specific)
    participant Assoc as Association
    participant AX as AthlasX Platform (W1-W9)

    U->>Auth: Open app, verify OTP
    alt New user
        Auth->>Onb: Route to Academy / Coach / Player onboarding
        Onb-->>Auth: onboardingComplete = true
    end
    Auth->>Dash: Route to role dashboard
    par Direct product path
        Dash->>AX: Player self-registers, appears in pool
    and Association data path
        Assoc->>AX: W1 ingest, W2 identity resolution
        AX->>AX: Player discovered, appears in pool
    end
    AX->>AX: W3 Trial cycle -> pre-camp dossier
    AX->>AX: W4 Selection committee -> squad locked
    AX->>AX: W5 Weekly tracking, in-season
    AX-->>AX: Longitudinal record enriches next cycle
Note: This is the key synthesis: there are two entry paths into the same player record pool. Direct self-registration (Player Onboarding, product-led) and association-data-discovery (W1/W2 ingest, institution-led) both converge into one player pool before the selection and tracking loop begins. The platform's whole value depends on those two paths writing to one canonical Player record, never two.
Site · Entry Point
Auth & Role Routing

Every session starts here: pick a role, verify a phone number, and get routed either into an onboarding wizard (new user) or straight to a dashboard (returning, onboarded user).

Actor: Any UserOutput: Routed to onboarding or dashboard
Sequence

Auth & Role Routing

sequenceDiagram
    participant U as User
    participant App as AthlasX App
    participant OTP as OTP Service
    participant Router as Role Router

    U->>App: Open app, select role
    U->>App: Enter mobile number
    App->>OTP: Send OTP
    OTP-->>U: SMS / WhatsApp OTP
    U->>App: Enter OTP
    App->>OTP: Verify OTP
    OTP-->>App: Verified
    App->>Router: Check onboardingComplete for role
    alt New user
        Router->>App: Redirect to onboarding wizard
    else Returning, onboarded
        Router->>App: Redirect to dashboard
    end

Pivot · Workflow 1
Association Onboarding & Historical Ingest

The gating workflow. Everything downstream depends on it, and its cost is set entirely by one variable: what form the association's records are already in.

Actors: AthlasX Ops, Association StaffOutput: Season live, association-verified
Sequence

Association Onboarding & Historical Ingest

sequenceDiagram
    participant Ops as AthlasX Ops
    participant Assoc as Association (Data Owner)
    participant Pipe as Ingest Pipeline
    participant W2 as Identity Resolution (W2)

    Ops->>Assoc: Approach with data-sharing proposal
    Assoc-->>Ops: Sign agreement (or decline)
    Ops->>Ops: Scope seasons, formats, age categories
    Ops->>Pipe: Audit source format
    Assoc->>Pipe: Hand over records / grant access
    alt Already on scoring platform
        Pipe->>Pipe: API / export sync
    else Digital scorecards
        Pipe->>Pipe: Structured parser
    else Scanned / paper
        Pipe->>Pipe: OCR + human review queue
    else Excel / registers
        Pipe->>Pipe: Column-mapping template
    end
    Pipe->>Pipe: Normalise to Tournament / Match / Performance
    Pipe->>W2: Send rows for identity resolution
    W2-->>Pipe: Resolved rows + confidence scores
    Pipe->>Assoc: Present normalised output for review
    Assoc-->>Pipe: Approve season (or send back for rework)
    Pipe->>Ops: Season live, association-verified
Note: Design flag: P0 (source format) is the single biggest cost driver in the business - determine it in the first conversation with any association, before signing. Given CricHeroes' penetration (23+ state associations), API/export sync should likely be treated as the primary path, not one of four equal branches.
Pivot · Workflow 2
Player Identity Resolution & Claim

Ingested performance rows refer to people who mostly do not have accounts. The platform creates and maintains shadow profiles that exist before any player signs up, then lets the real person claim one.

Actors: Player/Guardian, Association StaffOutput: Claimed or unclaimed player record in pool
Sequence

Player Identity Resolution & Claim

sequenceDiagram
    participant Row as Ingested Row (W1)
    participant Res as Resolution Engine
    participant Staff as Association Staff
    participant Player as Player / Guardian
    participant Auth as Auth Service

    Row->>Res: Performance row (name, team, academy, DOB, category)
    Res->>Res: Normalise name, handle transliteration
    alt High confidence (name+DOB+district)
        Res->>Res: Attach to existing shadow profile
    else Ambiguous
        Res->>Staff: Route to exception queue
        Staff-->>Res: Confirm / split / merge
    else No match
        Res->>Res: Create shadow profile (unclaimed, no login)
    end
    Res-->>Row: Player record in pool
    Player->>Player: Discovers profile (SMS / notice / search)
    Player->>Auth: Phone OTP
    alt Under 18
        Auth->>Player: Require guardian consent
        Player-->>Auth: Guardian consents
    end
    Auth->>Staff: Confirm identity (registration ID / DOB)
    Staff-->>Auth: Confirmed (or manual review)
    Auth-->>Player: Profile claimed, dashboard unlocked
    Player--)Auth: (any time) Withdraw consent
    Auth->>Res: Processing stops, profile delisted
Note: Hard requirement (source, Section 7): a large share of these players are minors - guardian consent is a precondition of activation, and withdrawal must be honoured at any point, not an afterthought.
Pivot · Workflow 3 · Core Loop
Trial Cycle → Pre-Camp Dossier

The wedge product. This is the workflow that must work perfectly before anything else ships - converting a registered trialist into a one-page, evidence-backed profile the selection panel sees before the camp.

Actors: Association, Player/Guardian, Selection PanelOutput: Every trialist retains a record
Sequence

Trial Cycle → Pre-Camp Dossier

sequenceDiagram
    participant Assoc as Association
    participant Player as Player / Guardian
    participant AX as AthlasX
    participant Panel as Selection Panel

    Assoc->>Assoc: Open trial cycle (age categories, DOB windows, fee)
    Assoc->>Player: Publish venues and dates
    Player->>Assoc: Register online (routed to DCA by pincode)
    Player->>Assoc: Pay fee
    Player->>AX: Upload documents (DOB, residency)
    Player--)AX: (optional) Attach footage
    AX->>AX: Match registrant to existing record (W2)
    alt Prior tournament history on file
        AX->>AX: Build dossier from tournament record
    else No history
        AX->>AX: Build thin dossier (declared history + footage)
    end
    AX->>AX: Compute percentile vs cohort (age + district)
    AX->>Panel: Generate and deliver pre-camp pack
    Panel->>Panel: Pre-read, flag players to watch
    Assoc->>Panel: Camp day, check-in by registration ID
    Panel->>AX: Grade on device during trial
    AX->>AX: Attach notes to permanent player record
    AX-->>Assoc: Every trialist retains a record
Note: Validation flag (source, Section 9, item 3): the dossier's headline pitch - converting a single over of cold first impression into confirmation of known ability - rests on the unverified one-over-vs-three-to-five-overs claim from a single player interview. Verify before it appears in an external pitch deck.
Pivot · Workflow 4
Selection Committee

Selection is a committee act. Independent grading first, convergence second, meeting third, recorded outcome last - deliberately resistant to a single loud voice anchoring the room.

Actors: Selection Panel, Association HeadOutput: Immutable selection record
Sequence

Selection Committee

sequenceDiagram
    participant Pool as Candidate Pool
    participant A as Selector A
    participant B as Selector B
    participant C as Selector C
    participant Conv as Convergence
    participant Head as Association Head

    Pool->>A: Filtered candidates (role/age/district/format)
    Pool->>B: Filtered candidates
    Pool->>C: Filtered candidates
    A->>Conv: Grade (blind to peers)
    B->>Conv: Grade (blind to peers)
    C->>Conv: Grade (blind to peers)
    Conv->>Conv: Build agreement view (unanimous/split/contested)
    alt Consensus reached
        Conv->>Conv: Resolve
    else No consensus
        Conv->>Conv: Committee session, side-by-side comparison
        Conv->>Conv: Resolve
    end
    Conv->>Conv: Lock squad (20-30 players)
    Conv->>Head: Written rationale per selection
    opt If enabled by association
        Conv->>Head: Rationale for notable omissions
    end
    Head-->>Conv: Immutable selection record confirmed
Note: Design flag: the notable-omissions rationale (G8) is off by default - correctly, for sales safety. But if no association ever turns it on, the platform never produces the one audit trail that would meaningfully differentiate it from a nicer dashboard. That trade-off is deferred here, not resolved.
Pivot · Workflow 5
In-Season Weekly Tracking

Applies to the selected squad only - 20 to 30 players. The design constraint is that this must create no new labour for anyone; the scorer's existing output is the input.

Actors: Association Scorer, CoachOutput: Season trend line, feeds next cycle's dossier
Sequence

In-Season Weekly Tracking

sequenceDiagram
    participant Scorer as Association Scorer
    participant AX as AthlasX
    participant Coach as Coach
    participant Sig as Signal Engine
    participant Sel as Selector

    Scorer->>Scorer: Record match, existing routine
    Scorer->>AX: Auto-ingest to player record
    Coach--)AX: (optional) Log session, attendance, fitness
    AX->>AX: Update weekly player card
    AX->>Sig: Check trend flag
    alt Form drop / workload / gap detected
        Sig->>Coach: Alert
        Sig->>Sel: Alert
    else No flag
        Sig->>Coach: Weekly digest only
    end
    Sig->>AX: Update season trend line
    AX-->>AX: Feeds next cycle's dossier (W3)
Note: Load-bearing assumption (source): if weekly tracking ever requires new data entry from anyone, it will not survive contact with a real season. Verify the scorer's existing workflow per association before promising this.
Pivot · Workflow 6
Player Development Loop

The player-side product. Free, and the reason players claim profiles - which is what makes the dataset real rather than administrative.

Actor: Player
Sequence

Player Development Loop

sequenceDiagram
    participant Player as Player
    participant AX as AthlasX
    participant Vis as Visibility Control

    Player->>AX: View own record (every match on file)
    AX-->>Player: Percentile vs cohort (age/district/role)
    AX-->>Player: Identified gaps vs next-level benchmark
    Player->>AX: Upload footage
    Player--)AX: (optional) Self-assessment
    Player->>Vis: Set visibility
    alt Default
        Vis->>Vis: Association only
    else Opt in
        Vis->>Vis: Selection panels across associations
    else Opt in, adult only (parked, phase 1)
        Vis->>Vis: Franchise and league scouts
    end
    Vis-->>Player: Trial and camp notifications
    Player->>AX: Registration deep link (-> W3)
Note: Default worth keeping: profile visibility defaults to association-only; franchise/scout-tier exposure is opt-in and adult-only, and explicitly parked for phase 1. Resist pressure to widen it early for a more impressive demo.
Pivot · Workflow 7
Coach

District or state squad coaches. Deliberately thin in phase 1 - the coach is a contributor to the record, not the primary customer, and advises selection rather than deciding it.

Actor: CoachOutput: Feeds weekly cycle (W5) and advisory input to W4
Sequence

Coach

sequenceDiagram
    participant Assoc as Association
    participant Coach as Coach
    participant AX as AthlasX
    participant Panel as Selection Panel

    Assoc->>Coach: Assign to squad
    Coach->>AX: View squad (20-30 players)
    Coach->>Coach: Plan session
    Coach->>AX: Mark attendance
    Coach->>AX: Log session notes (tied to players)
    Coach->>AX: Post-match review
    AX-->>Coach: Read-only player cards (form and workload trend)
    Coach--)Panel: Advisory input (-> W4)
    AX-->>AX: Feeds weekly cycle (W5)
Note: Permission model: read access to the pool, write access only to their own squad's notes, advisory-only input into W4. Do not over-invest here in phase 1 - this tier is already the most crowded part of the market.
Pivot · Workflow 8
Academy Affiliation Capture

Runs silently off W1. No academy signs up, no academy is sold to, and the academy dataset accumulates anyway - the byproduct that later becomes an inbound sales asset.

Actor: AthlasX OpsOutput: Ranked academy view - evidenced production, not claimed
Sequence

Academy Affiliation Capture

sequenceDiagram
    participant Row as Ingest Row (W1)
    participant Match as Match Engine
    participant Staff as Association Staff / Ops

    Row->>Match: Academy/club string
    Match->>Match: Normalise, fuzzy match to registry
    alt Confident match
        Match->>Match: Attach player to academy (date range)
    else Known variant
        Match->>Staff: Route to unmatched queue
        Staff-->>Match: Periodic manual reconciliation
    else Unseen academy
        Match->>Match: Create new academy stub
    end
    Match-->>Match: Build academy production record
    Match-->>Staff: Ranked academy view
    Staff--)Match: (later phase) Inbound academy signup
Note: Budget for mess: academy names arrive as free text - abbreviations, Hindi/English variants, branch suffixes. Do not assume clean joins; the reconciliation queue is an ongoing operational cost, not a one-time cleanup.
